# 项目技术报告

> **CustomBreakRecoverAnimation** —— 为《边狱公司》(Limbus Company) 实现的自定义混乱解除动画插件
> 作者：希希希土（Xt）　共同开发：DeepSeek
> 版本：v4.6　日期：2026-11

---

## 一、项目目标

让任意单位（含自制人格）在**混乱（Break）解除**时，播放**该单位自己的技能动作片段**，并且：

1. 支持**节选**（任意秒数区间），而不是只能整段播放
2. 播放期间固定位置与朝向
3. 语音与音效可分别静音
4. 可关闭技能动作携带的特效
5. 可控制镜头特写
6. **全部通过 JSON 配置**，使用者不需要写代码

### 为什么值得做

社区同类功能只能"整段播放一个动作"。而技能动作通常包含前冲、收招、长尾特效，
整段播放往往出现"人冲出去很远"或"动作拖沓"的问题。
**支持节选**是本项目与它们最实质的区别。

## 二、技术背景

| 项 | 内容 |
|---|---|
| 游戏引擎 | Unity 6000.3.12f1 |
| 脚本后端 | IL2CPP |
| 插件框架 | BepInEx 6（LimiNex）|
| 补丁库 | HarmonyX |
| 脚本系统 | ModularSkillScripts 5.3.5 |
| 目标框架 | .NET 6 |

ModularSkillScripts 提供了一套"JSON 里写脚本"的机制：脚本字符串被解析成
`TIMING`（何时）+ 函数序列（做什么）。插件通过注册
`MainClass.consequenceDict`（函数）与 `MainClass.timingDict`（时点）来扩展它。

## 三、架构

```
Plugin.cs                    注册时点 / 函数 / 补丁（每类单独 try-catch）
├── BreakPatches.cs          挂钩引擎的 4 条"解除混乱"路径，派发自建时点
├── Cq_BreakRecoverAnim.cs   函数 breakrecoveranim：解析参数 → 解除混乱 → 登记播放
├── Cq_AnimMode.cs           函数 animmode：8 个播放模式开关
├── BreakClip.cs             播放控制核心：定位、倍速、锁定、镜头、静音、收尾
├── RoundEndGuard.cs         回合推进信号 → 强制收尾，交还原版系统
├── HoldGuard.cs             播放期间阻止引擎刷新姿势
├── AudioMuteGuard.cs        静音兜底（`ChangeMotion` 前缀）
├── LateLock.cs              渲染前锁定兜底
├── RoundEndProbe.cs         诊断：带时间戳的回合流程探针
└── VanillaMotionProbe.cs    诊断：原版解混动作的行为记录
```

### 关键设计决策

**① 播放权交给引擎，我们只做控制**

```csharp
view.ReserveRoundEndAction(motion);   // 只登记，不主动播放
```

引擎随后调用 `PlayReservedRoundEndAction`，**只播一次**；我们接管 `PlayableDirector`
做定位与收尾。

> 早期版本同时调用 `OnRoundEndAction` + `ChangeMotion`，同一份 timeline 被播两次（特效重复）。

**② 动画开始即真正解除混乱**

```csharp
unit.RecoverAllBreak(...);   // 引擎状态
ca.OnRecoverBreak(true);     // 外观层
```

好处：
- 裁剪收尾后回退的是**闲置**姿势，而不是混乱姿势
- 不需要隐藏混乱 UI（状态已解除，UI 自然消失）

**③ 姿态保持 = 挂起引擎的刷新回调**

```csharp
act.Invoke();                              // 先刷新一次（让 UI 更新）
c.View.refreshRoundEndActions = null;      // 再挂起（姿势不再被刷新）
```

**④ 两个"结束时间"分开使用**

| 用途 | 用哪个 |
|---|---|
| 回合等待时长 | **动画轨内容结束时刻**（短，避免白等）|
| 锁定 / 收尾 | 持续到**回合推进信号**（长，避免残留位移）|

混用会导致两个 bug：等待过长（用 duration）或锁定提前解除（用内容长度当总长）。

## 四、失败方案记录（最有价值的部分）

以下全部经过实机验证，记录下来是为了避免他人重复投入。

| 尝试 | 结果 | 原因 |
|---|---|---|
| `Pause()` 定格末帧 | 回合结束卡 **10 秒** | 引擎认为动作未播完，等超时 |
| `Evaluate()` 定格 | **特效播两遍** | 重新计算 timeline，效果轨再次触发 |
| 漂移后 `ChangeMotion` 修复 | 每次修复特效 +1 | 等于重新启动动作 |
| `DestroyTrail()` / `SetDisableTrail()` | **贴图消失 + 游戏软锁** | 销毁了共享渲染对象 |
| 停用 `attackEffects` | 残留仍在 | 残留不在这里 |
| `Stop(StopEmittingAndClear)` 清粒子 | 残留仍在 | 残留不是粒子 |
| 强制回闲置收尾 | 残留仍在 | 与"动作结束判定"无关 |
| 改 `_roundEndDelay` / `TransitionDuration` | 完全无效 | 该字段不参与转场等待计算 |
| 裁结尾后保持姿势（4 种方案）| 全部失败 | `Stop` 与"定格"在引擎层面互斥 |
| 订阅 `Camera.onPreCull` | 无法编译 | 该 interop 里 `onPreCull` 是 Il2Cpp 结构体，不可 `+=` |
| `playskillanim`（任意时点播放）| 入场时无法播放 | `ChangeMotion` 只登记，引擎不驱动 director |

### 未解决的问题

**裁结尾的特效残留** —— 排查路径：

1. 停用攻击特效对象 → 无效
2. 停粒子系统 → 无效（唯一可见粒子属 UI）
3. 单位层级快照对比 → 只发现无关的 SP 条 UI
4. 场景根对象对比 → 未见新增
5. 强制回闲置 → 无效

结论：残留是**引擎在 timeline 层面持有的渲染状态**，外部无法在不破坏渲染器的前提下清理。
因此 v6.0 起明确取消所有清理，把取舍交给使用者。

## 五、结果与局限

### 已实现

节选播放、双端裁剪、真实解除混乱、位置与朝向锁定、语音/音效分别静音、
FX 屏蔽、姿态控制、镜头特写、水平反转、0.5~2 倍速、多单位同时触发。

### 局限

| 限制 | 性质 |
|---|---|
| 裁结尾姿势回闲置 | 引擎限制，无解 |
| 播放中位移无法完全消除 | 渲染时机受限 |
| 多单位等待取最长者 | 引擎设计 |
| 裁结尾特效残留 | 无安全清理手段 |
| 仅支持"强制解除"时点 | 设计选择（不改动原版自然解除）|

## 六、可复用的经验

1. **先探针、后推理**。本项目每个突破都来自探针日志，而不是猜测。
   带相对时间戳的日志是定位"谁在等谁"的唯一手段。
2. **不要与引擎抢控制权**。借用它的通道（`ReserveRoundEndAction` / `SelectFocus`），
   比自建播放系统可靠得多。
3. **区分"数据"与"登记"**。写字段 ≠ 调方法；引擎的列表驱动机制只认方法调用。
4. **IL2CPP 的三个陷阱**：
   - `GetType().Name` 对所有 timeline 轨都返回 `"TrackAsset"` → 按名字识别
   - `as` 转型会失败 → 用 `TryCast<T>()`
   - `IEnumerable` 不能直接 `foreach` → 转 `IEnumerator`
5. **破坏性接口一律禁用**。`Destroy*` 在共享资源上等于自杀，宁可功能不完美。
6. **区分"结果正确"与"机制生效"**。曾因"某单位没位移"误判抑制生效，
   实际是那个单位本来就没位移（`animationTracks=0` 这个信号被忽略）。
